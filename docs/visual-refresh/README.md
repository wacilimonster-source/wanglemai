## 现状视觉评审

评审依据为当前 Compose/RemoteViews 源码、原浏览器原型与仓库内截图。`docs/android-main.png` 为较早的暗色列表状态，仅辅助观察控件密度。`docs/android-main-light.png` 实际为启动画面，不能作为浅色列表截图。当前主屏布局判断以 `MainActivity.kt` 为准。`docs/android-widget-translucent-c.png` 用于观察既有半透明小部件。

| 观察 | 当前依据 | 本次处理 | 优先级 |
| --- | --- | --- | --- |
| 品牌偏冷，米色只承担背景 | Theme.kt 主色为 #215B45，白色 surface；深色为墨绿 | 奶油底 + 暖白内容面 + 深棕文字，焦糖色只强调主要操作 | P0 |
| 工具区视觉分量接近，内容出现偏晚 | 标题、OutlinedButton、OutlinedTextField、FilterChip 依次堆叠 | 选单轻底色、搜索去强描边、筛选合为分段控件，三组功能保持独立触点 | P0 |
| 列表像表单，缺少居家感 | 方形 Checkbox 与逐行 HorizontalDivider | 圆形完成控件、整组暖白内容面、细分隔线、标题与备注两级 | P0 |

| 用户的第一眼被控件占据 | 功能齐全，但标题、列表、操作层级不鲜明 | 标题负责情绪，列表负责内容，底部“记一条”负责行动 | P1 |

## 设计决定

以温馨简洁为优先，采用「奶油米、暖纸白、焦糖棕」。App 的内容面为实色，小部件承担玻璃材质。把光泽集中在小部件边缘，避免大面积透明文字底、强反光或繁复装饰。待办和待买复用同一套视觉，通过标签、数量和文案区分。

本次自主确定了焦糖色主按钮、暖深色配色、圆形完成控件和底部整宽新增入口，供产品评审确认。中文正文使用系统字体，提案页左侧宋体标题仅属于评审展板。

原型展示两份默认清单与单条编辑。自定义清单、批量录入、长期草稿、备份、更新、异常冲突流程的页面改造规格见开发说明。原型中的“管理清单”“备份”“更新”为明确标注的演示入口。配置页尺寸选择仅服务预览，保存提示仅确认当前预览配置。原型刷新后恢复初始演示数据。

## 原型使用

1. 左侧切换待办、待买、快速记录、配置及设置。
2. 在清单或右侧小部件中点圆圈，完成后可在 App 内 5 秒撤销。点正文编辑。
3. 搜索当前清单，切换未完成/已完成。
4. 点“记一条”输入，保存后 App 与右侧小部件同步。取消会退出此演示编辑器。
5. 切换深色壁纸检查玻璃层，再点“查看原生近似”比较底色与模糊差异。
6. 右上角切换暖深色，底部可重置演示数据。

## 平台依据

Android 官方将 AppWidget 的布局及交互限定在 RemoteViews 支持的视图集合内。现有实现也通过 RemoteViews 输出 XML 布局，因此将浏览器的 backdrop-filter 作为材质目标，原生基线采用 XML 半透明底色与描边。此方案是对当前实现的工程判断。细节见 [App widget overview](https://developer.android.com/develop/ui/views/appwidgets/overview)。

Widget 的格数与实际尺寸取决于 Launcher，按可用 dp 尺寸适配布局。官方支持 Android 12 起的响应式布局，并说明目标格数、最小尺寸与实际桌面空间的关系。本提案沿用现有 Provider 的标准 4×2、大号 4×4 定义。[Flexible widget layouts](https://developer.android.com/develop/ui/views/appwidgets/layouts)
