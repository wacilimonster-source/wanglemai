# 桌面小部件精修设计 · v1

2026-11-07。状态：原生实现已完成，验证结果见第10节。用户已确认“两行”是桌面占两排图标高度，不是事项文字换行。

## 1. 现状与问题

依据当前工作区源码及 `docs/visual-refresh/native/native-widget-light.png`、`native-widget-dark.png`。截图来自测试 Host，不代表用户当前 HyperOS 桌面的实际尺寸。工作区已有未提交的 Widget 修改，本方案依据其当前内容，不覆盖它们。

| 项目 | 当前值与行为 | 影响 |
| --- | --- | --- |
| 外观 | 24dp 圆角，四边 12dp 内边距 | 上下与左右没有区分，视觉重心较散 |
| 头部/底部 | 各至少 48dp | 连同上下 padding 固定占 120dp，矮卡片内容很少 |
| 密度 | 舒适 52dp；紧凑 44dp；正文都是 14sp | 紧凑只少 8dp 行高，操作区没有收紧 |
| 完成控件 | 20dp 圆环，48/44dp 触区 | 标题从 x=12dp 开始，事项从 x=60/56dp 开始，缩进关系生硬 |
| 数量 | 最大 64/60dp，无明确标题间距 | 长正文与数量容易挤在一起 |
| 容量 | `floor((H-120)/(52或44)×字号倒数)`；标准最多3，大号最多7 | 在 H=180dp 两档都只有1条；标准拉高也被3条限制 |
| 不完整行 | 当剩余达到一行的3/4时，允许强制放1条 | 预算与实际视图不一致时有裁切风险 |
| 两排尺寸 | 标准已声明目标4×2；minHeight=180，minResizeHeight=170dp | 已有名称与格数声明，但还没有专用矮版结构，不能等同于两排布局已做好 |
| 材质 | 浅色 #EBFFF8EA（92.2%），深色 #F0312920（94.1%） | 壁纸透色弱；整面渐变与全周高亮描边使边缘偏厚 |
| 配置预览 | 头尾40dp；示例事项前只有20dp圆圈+4dp间距；固定两条 | 与真实48dp头尾、48/44dp完成触区及实际容量不一致 |

## 2. 方向与布局规则

保留暖米色、圆角卡片、清单标题、圆形完成控件和单列事项。精修重点是对齐、有效内容量与克制的边缘光。

按桌面实际分配给卡片的可绘制宽高 W、H（dp）排版，不把“4×2”硬编码成一个尺寸。下文尺寸不包含 Launcher 自己添加的外部 inset；不再叠加额外外边距。格数由宿主决定，参考尺寸只用于设计验证。

- 舒适：H < 276dp 使用矮版，标题栏右侧放新增；H ≥ 276dp 保留现有标题—列表—底部操作三段结构。
- 紧凑：全部尺寸使用标题栏新增，标题本身打开清单，不再重复占一行显示“查看全部”。
- 两档正文均为14sp，密度通过空间分配区分，不缩小字体。
- 紧凑行高定为48dp（当前44dp），完整保留48dp触区；依靠回收底栏和减少内边距增加条数。
- 取消按 Provider 固定3/7条的显示上限，按空间放完整行；第一版设置12条渲染上限，超过时通过标题打开全部。不引入滚动列表。

## 3. 尺寸 token

| 尺寸项 | 舒适矮版 H<276 | 舒适常规 H≥276 | 紧凑全部尺寸 |
| --- | --- | --- | --- |
| 左右内容安全边 | 16dp | 16dp | 12dp |
| 上/下内边距 | 12 / 12dp | 12 / 12dp | 8 / 8dp |
| 标题栏高度 | 48dp | 48dp | 48dp |
| 标题栏到事项区 | 4dp | 0dp | 4dp |
| 单条事项高度 | 52dp | 52dp | 48dp |
| 单条事项之间额外 gap | 0 | 0 | 0 |
| 底栏高度 | 无 | 48dp | 无 |
| 事项与底栏额外 gap | 无 | 0 | 无 |
| 完成触区 | 48×48dp | 48×48dp | 48×48dp |
| 圆环可见尺寸 | 18×18dp | 18×18dp | 18×18dp |
| 圆环线宽 | 1.5dp | 1.5dp | 1.5dp |
| 圆环右缘至正文 | 15dp | 15dp | 15dp |
| 正文至数量最小间隔 | 8dp | 8dp | 8dp |
| 数量最大宽 | 64dp | 64dp | 56dp |
| 标题/正文/辅助文字 | 16 / 14 / 12sp | 同左 | 同左 |
| 字重 | 标题500，正文400 | 同左 | 同左 |
| 默认圆角 | 24dp，优先服从系统宿主圆角 | 同左 | 同左 |

对齐采用统一坐标：完成触区从卡片x=0开始，宽48dp；圆环居中于x=24dp，可见左缘x=15dp；正文从x=48dp开始，圆环右缘至正文15dp。标题从安全边x=16dp（舒适）或12dp（紧凑）开始，与圆环左缘形成近似同轴。行容器不能再叠加根布局的左右padding；正文触区从x=48dp开始，与完成触区无重叠。数量右缘对齐安全边。

正文单行末尾省略；取消用“• ”字符做置顶标记。置顶用正文附近12dp图钉图标，图标与文字4dp，不影响其他行的主对齐线。采购数量右对齐至安全边，圆环、正文、数量垂直居中。无数量时释放其占用空间。

## 4. 两排桌面小部件

目标保持4×2。推荐设计参考320×180dp，另外验证300×170、320×200、360×220dp；这些不是对 HyperOS 格子尺寸的承诺。

以320×180dp为例：

- 舒适：上12 + 标题栏48 + 间隔4 + 事项2×52 + 下12 =180dp，完整显示2条。
- 紧凑：上8 + 标题栏48 + 间隔4 + 事项2×48 + 余量16 + 下8 =180dp，同样显示2条。
- 320×200dp紧凑仍显示2条；第三条需要212dp总高，避免不完整行。
- 第3条紧凑事项出现的最小高度为212dp；舒适第3条需要232dp。
- 170dp高度：舒适1条、紧凑2条。空间不足时绝不塞入残缺行。

标题栏：左侧清单名及总数，整体为打开入口；右侧新增图标24dp、触区48×48dp，距右安全边对齐。标题和新增之间8dp。数量以“8项”显示，不显示重复类型标签。不增加装饰副标题。

常规舒适版在底栏继续使用“＋ 记一条”和“查看全部 ›”，保持熟悉的布局。紧凑及矮版标题显示“清单名 · 8项 ›”，末尾新增按钮，查看全部通过标题到达。

尺寸小于最小内容高度时：保留标题与新增；剩余不足完整一行就不显示事项。可用区域足够时显示“打开查看全部”。Provider 建议 minResizeHeight 从170dp降至144dp，用于宿主两排差异；144dp只保证1条，不宣称2条。保留旧版minHeight回退，Android12+优先4×2目标格数。实际能否缩到两排须由目标桌面验收。

## 5. 容量账本（字号100%，至少有足够多事项）

| 卡片实际高度H | 当前舒适/紧凑 | 提案舒适/紧凑 | 说明 |
| --- | --- | --- | --- |
| 144dp | 0 / 0 | 1 / 1 | 当前按3/4行补偿仍不足1行 |
| 170dp | 1 / 1 | 1 / 2 | 紧凑两条最低164dp |
| 180dp | 1 / 1 | 2 / 2 | 两排参考 |
| 200dp | 1 / 1 | 2 / 2 | 不为凑差异挤字 |
| 220dp | 1 / 2 | 2 / 3 | 紧凑多1条 |
| 240dp | 2 / 2 | 3 / 3 | 两档仍采用矮版 |
| 276dp | 3 / 3 | 3 / 4 | 舒适开始保留底栏 |
| 320dp | 3 / 3（标准）或3 / 4（大号） | 3 / 5 | 紧凑较舒适多2条 |
| 380dp | 3 / 3（标准）或5 / 5（大号） | 5 / 6 | 不再受标准3条限制 |
| 440dp | 3 / 3（标准）或6 / 7（大号） | 6 / 7 | 更高尺寸继续按空间增长 |

计算：舒适矮版 `floor((H-76)/52)`，舒适常规 `floor((H-120)/52)`，紧凑 `floor((H-68)/48)`；结果截到0…12。不做3/4行补偿。条数少时顶部对齐，不把行距拉大；剩余空间放在列表末尾，底栏固定在底部。表中现状依当前源码估算，不是设备实测。

大字号不能直接套100%容量表。字体1.3×及以上，先使用至少48dp和实测文字高度决定各区域，再减少事项条数。字体2×时应优先保留标题/新增/至少一条可完整容纳的事项；空间实在不够就仅保留入口。允许计数退出视觉显示，由无障碍描述读出总数。禁止截断文字上下沿。两档字号同步放大。

## 6. 玻璃材质

产品目标：暖、轻、边缘清楚，文字区域稳定。基线是标准RemoteViews可实现的半透明材质，不把浏览器实时模糊作为原生验收效果。

| 材质参数 | 浅色 | 深色 |
| --- | --- | --- |
| 主底色 | #FFF8EA，88%不透明（约#E0FFF8EA） | #312920，90%不透明（约#E6312920） |
| 面内渐变 | 白色8%→0%，从上到下 | 暖白4%→0% |
| 全周边线 | 1dp，白色36% | 1dp，#FFE9C9的14% |
| 内侧上沿高光 | 1dp，白色56%，只覆盖顶部弧线与上边缘 | 1dp，暖白22% |
| 下沿压边 | 1dp，#55412C的6% | 1dp，黑色12% |
| 外部阴影 | 不新增，交宿主处理 | 同左 |
| 文字、图标alpha | 1.0 | 1.0 |

正文颜色沿用当前#383129/#F4EADC，辅助#6F6050/#D3C2AC，操作#8A5335/#E5B68E。圆环需核验非文字对比，必要时用主操作色，不为柔和降低到看不见。避免双重白描边和整圈粗高光。

88/90%为提案初值。复杂照片、浅纯色、深纯色、黑白高频壁纸各测一组；普通文字对比目标4.5:1，圆环3:1。任一基准壁纸失败，则提高底色至浅92/深94%，再失败用96%或实色。以所有验收壁纸中最差结果选择默认token，不在运行时读取壁纸猜测背景。配置页和桌面使用同一材质参数。

原生不读取壁纸、不请求壁纸权限、不缓存桌面截图。只对卡片背景做半透明合成，文字不会被模糊。材质精致度主要来自边缘与色调，不能向用户承诺跨Launcher实时后景模糊。Android文档限定RemoteViews可用视图与方法；“不能依靠当前方案做跨宿主后景模糊”是结合该约束和当前代码的工程判断。

## 7. 状态、窄宽与配置

- 完成后：舒适常规沿用底栏“已完成 · 撤销”；矮版/紧凑将标题栏中原清单打开区域临时替换为“已完成 · 撤销”，保留右侧新增，避免新增反馈行挤掉内容。撤销结束恢复标题；无障碍描述说明原绑定清单。
- 冲突/失败：同位置显示“未完成，点此查看”，点击打开应用详情。优先级错误/冲突 > 撤销 > 正常标题/查看全部。错误详情不塞进两行小字。
- 空态：标题栏与新增不动；内容区最多两行“清单空空，想到就记”，14sp。不能因无内容变矮。
- 读取失败：内容区“暂时无法读取”，48dp高重试触区；新增仍可用。
- W≥280dp完整显示采购数量；240≤W<280dp数量最大48dp；180≤W<240dp隐藏数量、总数，正文保留，完整内容由无障碍与编辑页提供。标题始终单行省略；最小宽度180dp沿用。
- 采购单位过长按数量列末尾省略；正文与数量保持至少8dp，数量列不可吞掉全部正文。总数100+显示“99+项”，完整数量无障碍读出。
- 配置页用当前Provider及最新宿主尺寸绘制预览，保留固定预览舞台，卡片尺寸和内容条数按相同规则变化。切换密度显示“此尺寸预计显示2条/3条”；相同则如实显示相同，不用固定两条样例制造差异。
- 配置说明改为“显示条数随桌面尺寸和系统字号调整”，删除目前不成立的“至少保留1行”承诺。已有实例保持原密度、主题与绑定，不重置配置。

## 8. 开发交接与验收

276dp是经过容量校核的结构断点：舒适在275dp和276dp均显示3条，恢复底栏不会导致卡片拉高反而少一条。

后续实现涉及 `widget_content.xml`（常规/矮版结构）、事项布局、`WidgetRenderer`（标题栏与状态）、`WidgetUpdateCoordinator`（完整行容量、去除Provider3/7上限）、两个Provider尺寸声明、背景drawable和配置预览。不涉及数据结构或清单操作语义变更。

验收按180/240/320/360dp宽 × 144/170/180/200/220/240/320/380/440dp高分层取边界，特别检查163/164、179/180、211/212、231/232、275/276dp，字号100/130/200%，浅深主题与四类壁纸。逐项记录分配尺寸、实绘尺寸、行数、底部裁切、触区边界和对比。模拟器与HyperOS真机结果分列。

必须验证：320×180两档均2条、300×170舒适1/紧凑2、320×220舒适2/紧凑3、320×320舒适3/紧凑5；标题打开、新增、完成、编辑、撤销、多实例、调整尺寸后刷新。所有触区至少48×48dp且不重叠；尺寸不足显示入口，不强塞一行。两个预览与桌面采用相同token与容量规则。

平台资料：[响应式尺寸与目标格数](https://developer.android.com/develop/ui/views/appwidgets/layouts)、[Widget布局与RemoteViews约束](https://developer.android.com/develop/ui/views/appwidgets/overview)、[系统圆角与增强](https://developer.android.com/develop/ui/views/appwidgets/enhance)。

## 10. 原生实现与验证 · 2026-11-07

原生端已应用本方案。桌面与配置预览共用 `WidgetLayout`、`WidgetRenderer` 和 `WidgetGlass`。Android12及以上使用宿主提供的多尺寸列表，较早版本使用尺寸范围回退，首次配置时的0×0尺寸回退到标准参考尺寸。

浅色底板最终采用92%不透明度。88%初值在极暗壁纸上的辅助文字最低对比为4.35，低于4.5目标。提高后正文、辅助文字和操作色最低对比分别约10.17、4.81、4.95。深色90%底板对应最低对比约8.84、6.05、5.72。以上为8个RGB极值背景上的底色合成计算，真机壁纸合成效果仍待验收。

构建、58项JVM测试及Lint通过，Lint报告0错误、55项警告。Android14/API34模拟器 `emulator-5554` 的9项小部件相关测试通过，覆盖真实RemoteViews的行数边界、字体100/130/200%、180/240/320dp宽度、48dp触区、窄宽数量处理、错误与撤销反馈，以及真实AppWidgetHost的多尺寸选择、动态调整、完成撤销、新增、独立配置和取消配置。

真实宿主确认170dp高显示舒适1条/紧凑2条，180dp为2/2，220dp为2/3，320dp为3/5。标准Provider拉高后同样按空间显示条数。测试同时覆盖首次配置的0尺寸回退。

原生截图位于 `native/comfortable-light.png`、`native/comfortable-dark.png`、`native/compact-light.png` 和 `native/compact-dark.png`。这些为320×320dp的真实RemoteViews绘制结果，背景为固定暖绿色。设计浏览器验证与本节原生验证分别记录于 `verification.json`、`verification-native.json`。

目标HyperOS桌面的实际两排占格、重启恢复及不同真机壁纸显示效果，保留为真机验收项目。安装包位于 `app/build/outputs/apk/debug/app-debug.apk`。

## 12. v0.3.2修正

用户真机反馈原144dp缩放下限仍对应三排。标准与大清单现在都使用110dp传统最小高度、56dp纵向缩放下限。标准目标4×2，大清单目标4×4，实际占格由桌面网格及宿主边距共同决定。低高度时自动压缩边距，110dp参考高度两档原布局都可以容纳一条完整事项。

新增超紧凑档，标题栏和事项行36dp，左右8dp、上下4dp，标题与正文14sp，完成点击区36×36dp。170dp高显示3条、320dp高显示7条，系统字体放大时按实测文字高度增高。已保存的舒适和紧凑配置通过原枚举名称读取，新档位独立保存。

配置页的返回键、返回手势、取消和保存成功后直接回到系统桌面。取消保留原配置，保存中消费返回事件，提交完成后退出。专项测试在App主界面位于配置页下方时验证三种退出都抵达真正的默认Launcher。

58项JVM测试通过。37项设备用例完成验证，其中清单管理用例补齐异步等待后单独补跑通过。完整记录见verification-0.3.2.json及docs/evidence。目标HyperOS真机实际占格和旧实例缓存仍待验证。尺寸声明遵循[Android小部件尺寸规则](https://developer.android.com/develop/ui/views/appwidgets/layouts)。
